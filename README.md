# Selection coefficients from clonal copy-number data

Given the copy-number profiles of the clones inside a tumour, infer the **44 chromosome-arm
selection coefficients** (22 chromosomes × p/q arms) that produced it.

Tumours are generated by a forward clonal-evolution simulator (SISTEM), and a **neural posterior
estimator** — a normalising flow conditioned on a learned embedding of the tumour's clone set —
is trained on those simulations to approximate the posterior over the 44 coefficients. Three
embeddings are compared. The flow and the training loop are identical in all three, so the
comparison is purely about how the clone set is summarised before the flow sees it.

Each training example is one simulation: **25 replicate tumours grown from a single θ**, with
θ ~ N(0, 0.2) independently per arm.

## The three models

| Name | Encoder | What it sees |
| --- | --- | --- |
| **CloneMLP-NPE** | per-clone MLP, frequency-weighted mean pooling | 100 most frequent clone profiles × (44 arms + frequency) |
| **CloneAtt-NPE** | Set Transformer (3 × ISAB + PMA) | the same clone set |
| **DominantClone-NPE** | DeepSet over trials | the largest clone only, 44 values per trial |

All three are defined as frozen presets in [`src/cancer_sbi/config.py`](src/cancer_sbi/config.py),
one `ModelPreset` each, recording the encoder, flow, optimiser and training settings that the
original per-folder scripts used.

## Results

From 651 held-out simulations (707 for DominantClone), 5,000 posterior draws each. Full tables in
[`results/`](results/).

| Model | true R² | squared Pearson r² | validation NLL | SBC failures (FDR) |
| --- | --- | --- | --- | --- |
| CloneMLP-NPE | **0.472** | 0.527 | −21.96 | 39 / 44 |
| DominantClone-NPE | 0.170 | 0.177 | −11.65 | **0 / 44** |
| CloneAtt-NPE | 0.049 | 0.063 | −9.12 | 21 / 44 |

Two reference rows matter for reading the table. The **prior bar** is the differential entropy of
N(0, 0.2007) in 44 dimensions, −8.23 nats: the loss a model gets by ignoring the data entirely.
The **ridge baseline** ([`src/baselines/`](src/baselines/)) is a linear fit to four copy-state
statistics per arm, and it is currently the strongest point estimator here.

Note that **true R² and squared Pearson r² are different quantities** and the gap between them is
not noise — it measures systematic scale-and-offset error in the posterior mean. Quote true R² when
comparing against the ridge baseline, which is itself a true R².

### Figures

| File | Question it answers |
| --- | --- |
| `fig_A_coverage` | Are the credible intervals honest? Empirical vs nominal coverage |
| `fig_B_contraction_zscore` | Which arms did the model actually learn? One point per arm |
| `fig_C_sbc_ecdf` | Simulation-based calibration: is the true θ a typical posterior draw? |
| `fig_D_shrinkage` | Posterior mean against truth — where the systematic error lives |

Each is written as both `.png` (320 dpi) and `.pdf` (vector). `fig_D` also has a `_poster` build
with the title dropped and type enlarged.

### Two evaluation paths, deliberately

`cancer_sbi/evaluation/` holds both:

- `diagnostics.py`, `figures.py`, `posterior.py` reproduce the **original** per-model figures —
  z-score histograms and violins, KDE prior-vs-posterior, posterior pairplots, the true-vs-posterior
  -mean scatter grids and the correlation spreadsheet. Driven by `cli/evaluate.py`.
- `sample_posteriors.py`, `poster_metrics.py`, `fig_shrinkage.py` are the **newer** suite: one GPU
  pass writes every posterior draw to an `.npz`, and each metric afterwards is a numpy recompute
  taking under a minute. This is where coverage, contraction, true R² and FDR-corrected SBC live.

## The dataset

Not in version control. It lives on the cluster at `~/cancer/data/Guassian_Normal/simulation_outputs`
(3,600 simulations, ~14 GB); a partial 888-simulation subset is kept locally for testing.

```
simulation_outputs/
  sim<N>/
    parameters.pkl          46 floats; [2:] are the 44 selection coefficients.
                            The first two are nuisance rates the models never predict.
    <1..25>/                one directory per replicate tumour
      CNratios_all.pkl.gz   (n_cells, 44) log2 copy-number ratios - what CloneMLP/CloneAtt read
      results.pkl           3-tuple; [1] is the largest clone - what DominantClone reads
      sim.log
```

Properties worth knowing before modelling against it:

- A typical replicate has **~1,600 distinct clone profiles**, so `top_k=100` is a hard truncation
  covering a median of only **45%** of cells. There is no dominant clone: the largest is typically
  1.5% of the population.
- **19.9%** of copy-number entries are exactly −10.966, the sentinel for total arm loss, and
  **52.1%** are exactly 0. Overall standard deviation 4.34.
- Replicates of the same simulation correlate at r ≈ 0.74, so the 25 trials carry real stochastic
  variation rather than being near-copies.

`docs/DATA_GENERATION.md` (local, not tracked) is the authoritative reference for how the
simulations were produced.

## Running it

The package is configured by environment variable or by flag:

```bash
export CANCER_SBI_DATA_ROOT=~/cancer/data/Guassian_Normal/simulation_outputs
export CANCER_SBI_SPLIT=~/cancer/data/train_test_split.pkl
export CANCER_SBI_RUNS=~/cancer/runs
```

On the cluster, everything goes through SLURM — `/home` is mounted `noexec`, so nothing runs on the
login node:

```bash
cd ~/cancer/src
sbatch jobs/sample.sh                    # draw posteriors, all three models
sbatch jobs/analyze.sh                   # metrics + figures A, B, C
sbatch jobs/shrink.sh                    # figure D
EXTRA="--limit 4" sbatch jobs/sample.sh  # smoke test
```

Or directly:

```bash
python -m cancer_sbi.evaluation.sample_posteriors --model clonemlp --out-dir results/posteriors
python -m cancer_sbi.evaluation.poster_metrics --in-dir results/posteriors --out-dir results
python -m cancer_sbi.cli.train --model clonemlp --ckpt-dir runs/clonemlp
```

Inside any job script, after `conda activate`:

```bash
export LD_LIBRARY_PATH="$CONDA_PREFIX/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
```

Without it, conda's SciPy fails to load against the system `libstdc++`.

## Verifying the refactor

`cancer_sbi` is a refactor of three sets of per-model scripts. `verify_refactor.py` proves it
computes the same things — not approximately, element by element:

```bash
python src/verify_refactor.py \
    --data-root data/Guassian_Normal/simulation_outputs \
    --legacy-root _archive_2026-09-23 \
    --with-models
```

It checks the data pipeline (identical tensors out of `top_frequent_rows_tensor` and both dataset
classes), model construction (identical parameter names, shapes, initial weights under a fixed seed,
and forward passes) and every configuration value. **42 of 42 checks pass** on both the laptop and
the cluster. `--legacy-root` points at the archived original folders.

## Environment

Conda environment `cancer` locally, `cancer-sbi` on the cluster: `torch`, `sbi` 0.25.0, NumPy ≥ 2
(the pickles were written with it), plus `sistem` and `mpi4py` for the simulators.
